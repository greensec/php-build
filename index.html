php-build

Debian packages of PHP for suites that packages.sury.org no longer builds.

What is this?

Sury stopped publishing packages for end-of-life Debian releases - the bullseye pool was deleted upstream. This repository rebuilds the current PHP upstream releases with sury's own packaging (from the bookworm source packages) inside clean containers of the target suite, and publishes the result as a signed APT repository on GitHub Pages.

The package set is identical to what sury would have shipped: all SAPIs (cli, fpm, cgi, phpdbg, embed, apache2, litespeed) and the full extension set. Runtime dependencies are pinned to the distro's own libraries during the build, so the packages install on a plain bullseye/buster system - no other third-party repository is required at install time.

Source and build pipeline: github.com/greensec/php-build.

Installation

Import the signing key and add the repository (replace <dist> with bullseye or buster):

curl -fsSL https://greensec.github.io/php-build/public.key \
  | gpg --dearmor -o /etc/apt/keyrings/php-build.gpg

echo "deb [signed-by=/etc/apt/keyrings/php-build.gpg] \
https://greensec.github.io/php-build/repo <dist> main" \
  > /etc/apt/sources.list.d/php-build.list

apt-get update
apt-get install php8.4-cli php8.4-fpm   # or any php<branch>-<ext>

Equivalent helper: add-repository.sh.

Details

  • Architecture: amd64 only.
  • Suites: bullseye (and buster once published); each suite is self-contained - plain Debian archive + this repo is enough to install.
  • Version scheme: <upstream>-<debian-rev*1000+1>~<dist><build-id>, e.g. 8.2.36-2001~bullseye20. The trailing build id makes every rebuild of the same upstream version unique and upgradeable.
  • Signing: dedicated GPG key, public.key (also served as public.gpg); InRelease is signed.
  • Packaging source: unmodified sury debian/ tree for the newest supported suite, plus the newest upstream security tarball.
  • Builds: GitHub Actions on a self-hosted runner, reproducible via workflow_dispatch; EOL branches (5.6-8.1) can be rebuilt from php-src-security backports.
Not affiliated. Unofficial rebuilds - not provided by Ondrej Sury, the Debian PHP team, or Debian security. If a dist-upgrade path exists for your hosts, prefer it; this repo is a bridge for systems that must stay on an EOL suite.
Mixing with sury. These packages supersede the stale sury copies cleanly (higher version), and the repo can coexist with a sury mirror. It intentionally does not ship sury's backported libraries (pcre2 10.40, libgd3 2.3.3, ...), so packages satisfy the distro's own versions.
